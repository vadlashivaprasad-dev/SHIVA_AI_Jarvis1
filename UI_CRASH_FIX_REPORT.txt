Step 1) Identify UI crash trigger in Chat UI
-------------------------------------------------
File checked: apps/web/src/components/Chat.tsx

Finding:
- The Retry handler called sendMessage(...) by passing a fake React.FormEvent:

  await sendMessage({ preventDefault: () => {} } as unknown as React.FormEvent)

- sendMessage expects a real FormEvent and immediately calls e.preventDefault().
- Passing a fabricated event object is fragile and can cause runtime issues depending on React/browser behavior.

Action taken:
- Refactored the actual send logic into a separate callback named doSendMessage().
- Updated:
  - form submit handler to call doSendMessage() via sendMessage(e)
  - Retry button handler to call doSendMessage() directly (no fake event)

Code-level outcome:
- Retry now cannot trigger event-shape related crashes.

-------------------------------------------------
Step 2) Confirm backend-side fix for tool history error
-------------------------------------------------
File checked: services/gateway/src/llm.py

Finding:
- OpenAICompatibleProvider.generate builds an OpenAI-compatible payload.
- There was already (after previous work) logic that sanitizes history to avoid
  orphan tool messages that OpenAI rejects:

  - It drops message.role == "tool" when there is no matching tool_calls context.

Action taken / state:
- Verified sanitization exists in current llm.py implementation.

Code-level outcome:
- Outbound messages payload for /chat/completions should not include invalid
  orphan tool messages (role:'tool') that trigger the OpenAI 400 error.
